## 🎯 ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

**WB Slots** — это комплексная система автоматизации для работы с маркетплейсом Wildberries, предназначенная для автоматического поиска и бронирования слотов поставки товаров на склады WB.

### Основное назначение:
- 🔍 Автоматический поиск доступных слотов для поставок
- ⏰ Мониторинг изменений в расписании складов
- 🤖 Автобронирование найденных слотов (экспериментально)
- 📦 Управление типами тары и предпочтениями складов
- 🔔 Уведомления через Telegram и Email
- 📊 Аналитика и статистика работы

## 📊 АНАЛИЗ БАЗЫ ДАННЫХ

### Основные модели (Prisma Schema)

#### 1. **User** — Пользователи системы
- Поддержка ролей: USER, ADMIN, DEVELOPER
- Мультитенантность с изоляцией данных
- Защита пользователей (isProtected)
- Связи: токены, задачи, склады, сессии, уведомления

#### 2. **UserToken** — Токены WB API
- Шифрование токенов (tokenEncrypted)
- Категории: STATISTICS, SUPPLIES, MARKETPLACE, CONTENT, PROMOTION, ANALYTICS, FINANCE
- Отслеживание использования (lastUsedAt)

#### 3. **Task** — Задачи поиска слотов
- Уникальный номер задачи (taskNumber)
- Фильтры в JSON формате
- Расписание через Cron (scheduleCron)
- Автобронирование (autoBook, autoBookSupplyId)
- Статусы: PENDING, RUNNING, SUCCESS, FAILED, STOPPED, BOOKING, COMPLETED

#### 4. **Run** — Выполнения задач
- Связь с задачей и пользователем
- Статусы: QUEUED, RUNNING, SUCCESS, FAILED, PARTIAL, CANCELLED, COMPLETED
- Сводка в JSON формате
- Логи выполнения (RunLog)

#### 5. **FoundSlot** — Найденные слоты
- Информация о складе, дате, времени
- Коэффициент и доступность
- Типы тары (boxTypes)
- Уникальное ограничение на активные бронирования

#### 6. **WBSession** — Сессии Wildberries
- Зашифрованные данные сессии (sessionData)
- Валидация и срок действия
- Аудит использования

#### 7. **BookingResult** — Результаты бронирования
- Статусы: SUCCESS, FAILED, PENDING, CANCELLED
- Детали бронирования в JSON

#### 8. **BookingLock** — Блокировки для автобронирования
- Предотвращение одновременных бронирований
- TTL для автоматического освобождения

#### 9. **NotificationChannel** — Каналы уведомлений
- Типы: EMAIL, TELEGRAM, WEBHOOK
- Конфигурация в JSON

#### 10. **AuditLog** — Аудит действий
- Логирование всех действий пользователей

#### 11. **SecurityEvent** — События безопасности
- Типы: LOGIN, LOGOUT, SESSION_CREATED, SUSPICIOUS_ACTIVITY, AUTH_FAILED, CAPTCHA_DETECTED

### Индексы и оптимизация:
- ✅ Индексы на часто используемых полях (userId, status, createdAt)
- ✅ Уникальные ограничения для предотвращения дубликатов
- ✅ Каскадное удаление связанных записей

## 🔧 АРХИТЕКТУРНЫЕ ПАТТЕРНЫ

### 1. Унифицированная архитектура сервисов

Проект прошел масштабный рефакторинг для устранения дублирования:

**До рефакторинга:**
- 4 версии сервисов поиска слотов
- 4 версии сервисов автобронирования
- 4 версии сервисов уведомлений
- 2 версии WB API клиентов

**После рефакторинга:**
- ✅ Единые интерфейсы (`unified-interfaces.ts`)
- ✅ Базовый класс сервисов (`base-service.ts`)
- ✅ Менеджер сервисов (`service-manager.ts`)
- ✅ Унифицированные сервисы:
  - `UnifiedWBAPIClient`
  - `UnifiedSlotSearchService`
  - `UnifiedAutoBookingService`
  - `UnifiedNotificationService`

### 2. SOLID принципы

Проект следует принципам SOLID:
- **S**ingle Responsibility — каждый сервис отвечает за одну задачу
- **O**pen/Closed — расширяемость через интерфейсы
- **L**iskov Substitution — базовые классы с общим поведением
- **I**nterface Segregation — разделенные интерфейсы
- **D**ependency Inversion — зависимость от абстракций

### 3. Паттерны проектирования

- **Singleton** — для глобальных сервисов (BrowserManager, SessionManager)
- **Factory** — создание клиентов WB API
- **Strategy** — различные стратегии поиска и бронирования
- **Observer** — система уведомлений
- **Queue** — асинхронная обработка задач через BullMQ
