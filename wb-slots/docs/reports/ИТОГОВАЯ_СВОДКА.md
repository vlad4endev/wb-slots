### **2. Разделение токена API и WB сессии** ✅

#### **Важно!** Теперь система различает:

| Что | Для чего | Требуется |
|-----|----------|-----------|
| **Токен API (SUPPLIES)** | Поиск слотов<br>Получение складов<br>Получение поставок | ✅ Обязательно для API |
| **WB Сессия (браузер)** | Автобронирование через Playwright | ✅ Обязательно для автобронирования |

#### Результат:
- ✅ Автобронирование **НЕ требует** токен API
- ✅ Поиск слотов **НЕ требует** WB сессию
- ✅ Правильное разделение зон ответственности

## 📋 Инструкция по проверке проблемы

### **Если автобронирование не включается:**

1. **Откройте:** http://localhost:3000/debug-wb-session

2. **Проверьте блок "Автобронирование доступно":**
   - **Да ✅** → Всё работает, можно создавать задачу
   - **Нет ❌** → Смотрите ошибку ниже

3. **Если "Нет активной сессии Wildberries":**
   - Нажмите **"Обновить всё"**
   - Посмотрите раздел **"Все WB сессии"**
   - Если список пуст → **Авторизуйтесь через WB Auth**

4. **Откройте консоль (F12)** и найдите:
   ```
   📊 useAutoBookingCheck: данные ответа
   ```
   Проверьте `hasSession: true/false`

5. **Нажмите "Проверить API"** на странице отладки
   - Посмотрите JSON ответ
   - Должно быть `"hasSession": true`

## 🔄 Как создать WB сессию

**Если сессии нет:**

1. Перейдите: http://localhost:3000/wb-auth

2. Выберите метод:
   - **Popup** (рекомендуется)
   - **Enhanced**

3. Введите:
   - Номер телефона (например: +79001234567)
   - Код из СМС

4. Дождитесь сообщения: "✅ Сессия создана успешно"

5. Вернитесь на `/debug-wb-session`

6. Проверьте статус - должно быть: **Да ✅**

## 📊 Проверка в базе данных

Если нужно проверить напрямую в БД:

```sql
-- Все WB сессии текущего пользователя
SELECT 
  id,
  is_active,
  created_at,
  last_validated,
  expires_at,
  deactivation_reason
FROM wb_sessions
WHERE user_id = 'ваш_user_id'
ORDER BY created_at DESC;
```

**Что должно быть:**
- Минимум 1 запись
- `is_active = true`
- `last_validated` свежая (не старше 7 дней)
- `expires_at` либо `NULL`, либо в будущем
