## 🔧 Решения проблем

### **Проблема 1: "Нет WB сессий"**

**Что делать:**
1. Перейдите в **WB Auth** → http://localhost:3000/wb-auth
2. Выберите метод авторизации:
   - **Popup** - быстрая авторизация
   - **Enhanced** - расширенная авторизация
3. Введите телефон и код из СМС
4. Дождитесь успешной авторизации
5. Вернитесь на `/debug-wb-session`
6. Нажмите **"Обновить всё"**

**Результат:** Должна появиться активная WB сессия

---

### **Проблема 2: "Сессия есть, но неактивна"**

**Признаки:**
- В списке есть сессия
- Статус: Неактивна ❌
- Есть причина деактивации

**Причины:**
- `expired` - истёк срок действия (> 7 дней)
- `expired_by_age` - сессия старая
- `manual` - деактивирована вручную

**Что делать:**
1. Создайте новую WB сессию (см. Проблему 1)
2. Старые сессии можно игнорировать

---

### **Проблема 3: "API возвращает hasSession: true, но хук показывает false"**

**Что проверить:**

1. **На странице отладки нажмите кнопки:**
   - "Проверить API" → смотрите ответ
   - "Обновить всё" → обновляет хук и API

2. **Сравните результаты:**
   ```
   API ответ:  hasSession: true
   Хук статус: canAutoBook: false  ← Не совпадают!
   ```

3. **Если результаты не совпадают:**
   - Очистите кэш браузера (Ctrl + Shift + Del)
   - Перезагрузите страницу (Ctrl + F5)
   - Проверьте снова

4. **Посмотрите логи в консоли:**
   - Есть ли ошибки React?
   - Правильно ли парсится JSON ответ?

---

### **Проблема 4: "Сессия в базе есть, но API не находит"**

**Проверьте в логах сервера:**

Найдите лог:
```
🔍 Проверка WB сессии для пользователя: clxxx...
📊 Результат поиска WB сессии: {
  found: false,  ← Почему false если сессия есть?
  sessionId: null,
  isActive: null
}
```

**Возможные причины:**
1. **userId не совпадает** - проверьте что userId в сессии совпадает с текущим пользователем
2. **isActive = false** - сессия деактивирована
3. **Проблема с БД** - проверьте подключение

**SQL для проверки:**
```sql
SELECT * FROM wb_sessions 
WHERE user_id = 'ваш_user_id' 
AND is_active = true
ORDER BY last_validated DESC;
```

## 📊 Debug информация на странице

В нижней части страницы `/debug-wb-session` есть блок:

```
Debug информация:
canAutoBook: ❌ false
isCheckingSession: ❌ false
sessionError: Нет активной сессии Wildberries...
Всего WB сессий: 0
Активных WB сессий: 0
```

**Что смотреть:**
- `canAutoBook` → должно быть `true` для автобронирования
- `Активных WB сессий` → должно быть > 0
- `sessionError` → должно быть `null` если всё ОК

## ✅ Контрольный чеклист

Для работы автобронирования нужно:

- [ ] WB сессия существует в БД (таблица `wb_sessions`)
- [ ] WB сессия активна (`is_active = true`)
- [ ] WB сессия не истекла (`last_validated` не старше 7 дней)
- [ ] API `/api/wb-session/check` возвращает `hasSession: true`
- [ ] Хук `useAutoBookingCheck()` возвращает `canAutoBook: true`
- [ ] В форме создания задачи кнопка автобронирования активна

**Если все пункты ✅ - автобронирование должно работать!**
