# 🔍 Отладка проблемы с WB сессией

## 🐛 Проблема
Сессия активна, но в форме создания задачи отображается что нет авторизации.

## 🛠️ Как проверить и исправить

### **Шаг 1: Откройте страницу отладки**

Перейдите по ссылке: **http://localhost:3000/debug-wb-session**

Эта страница покажет:
- ✅ Статус WB сессии из хука `useAutoBookingCheck()`
- 📡 Прямой ответ от API `/api/wb-session/check`
- 📋 Список всех WB сессий в базе данных
- 🔍 Детальную debug информацию

---

### **Шаг 2: Проверьте консоль браузера**

Откройте консоль (F12 → Console) и найдите логи:

```
🔍 useAutoBookingCheck: проверка WB сессии...
📡 useAutoBookingCheck: ответ получен { status: 200, ok: true }
📊 useAutoBookingCheck: данные ответа { 
  success: true, 
  hasSession: true/false,
  message: "..."
}
```

**Что смотреть:**
- `hasSession: true` → сессия найдена ✅
- `hasSession: false` → сессия НЕ найдена ❌
- `error` → ошибка при проверке ⚠️

---

### **Шаг 3: Проверьте ответ API**

На странице отладки нажмите **"Проверить API"**

**Ожидаемый ответ при активной сессии:**
```json
{
  "success": true,
  "data": {
    "hasSession": true,
    "sessionId": "clxxx...",
    "lastActive": "2024-11-01T12:00:00.000Z",
    "message": "Активная сессия Wildberries найдена"
  }
}
```

**Ответ при отсутствии сессии:**
```json
{
  "success": true,
  "data": {
    "hasSession": false,
    "message": "Нет активной сессии Wildberries..."
  }
}
```

---

### **Шаг 4: Проверьте базу данных**

На странице отладки посмотрите раздел **"Все WB сессии"**

**Что проверить:**
- Есть ли сессии вообще?
- Есть ли активные сессии (`isActive: true`)?
- Когда была последняя валидация?
- Не истекла ли сессия?

**Пример активной сессии:**
```
ID: clxxx...
Статус: Активна ✅
Создана: 01.11.2024 10:00
Последняя валидация: 01.11.2024 12:00
Истекает: 08.11.2024 10:00 (через 7 дней)
```

**Пример истекшей сессии:**
```
ID: clxxx...
Статус: Неактивна ❌
Создана: 25.10.2024 10:00
Последняя валидация: 25.10.2024 10:00
Деактивирована: 01.11.2024 12:00
Причина: expired_by_age
```

## 🔧 Возможные причины и решения

### **Причина 1: Нет WB сессий в базе**

**Признаки:**
- Раздел "Все WB сессии" пустой
- `hasSession: false`

**Решение:**
1. Перейдите в **WB Auth** (`/wb-auth`)
2. Выберите метод авторизации (Popup или Enhanced)
3. Авторизуйтесь через Wildberries
4. Вернитесь на страницу отладки
5. Нажмите "Обновить всё"

---

### **Причина 2: Сессия есть, но `isActive: false`**

**Признаки:**
- Сессия есть в списке
- Статус: "Неактивна"
- `hasSession: false`

**Решение:**
1. Проверьте причину деактивации
2. Если `expired` - создайте новую сессию через WB Auth
3. Если другая причина - смотрите логи сервера

---

### **Причина 3: Сессия активна, но хук возвращает `false`**

**Признаки:**
- В разделе "Все WB сессии" есть активная сессия
- API возвращает `hasSession: true`
- Но хук показывает `canAutoBook: false`

**Возможная проблема:** Ошибка в логике хука или кэширование

**Решение:**
1. Очистите кэш браузера (Ctrl + Shift + Delete)
2. Перезагрузите страницу (Ctrl + F5)
3. Проверьте консоль на наличие ошибок React
4. Попробуйте закрыть и открыть форму заново

---

### **Причина 4: Сессия истекла по времени**

**Признаки:**
- Сессия была создана более 7 дней назад
- `lastValidated` старше 7 дней
- `hasSession: false`

**Решение:**
1. Система автоматически деактивирует старые сессии
2. Создайте новую сессию через WB Auth
3. Новая сессия будет действовать 7 дней

## ✅ Быстрое решение

### **Если ничего не помогает:**

1. **Полная переавторизация:**
   ```
   1. Перейдите в WB Auth
   2. Нажмите "Logout" (если есть сессия)
   3. Авторизуйтесь заново
   4. Проверьте на странице отладки
   ```

2. **Очистка кэша:**
   ```
   1. Ctrl + Shift + Delete
   2. Очистить cookies, кэш
   3. Перезагрузить страницу
   4. Попробовать снова
   ```

3. **Проверка базы данных:**
   ```sql
   -- Посмотреть все WB сессии для вашего пользователя
   SELECT * FROM wb_sessions 
   WHERE user_id = 'ваш_user_id' 
   ORDER BY created_at DESC;
   ```
