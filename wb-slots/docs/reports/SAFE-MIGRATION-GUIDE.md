# 🛡️ БЕЗОПАСНАЯ МИГРАЦИЯ СЕССИЙ - РУКОВОДСТВО

## ✅ Что было сделано для защиты существующих данных:

### 1. **Обратная совместимость**
- ✅ Код автоматически определяет старый формат (`cookiesEncrypted`, `localStorageEncrypted`, `sessionStorageEncrypted`) и новый формат (`sessionData`)
- ✅ При чтении старых сессий автоматически выполняется миграция в новый формат
- ✅ Миграция происходит в фоновом режиме, не блокируя текущие операции

### 2. **Безопасная схема БД**
- ✅ Поле `expiresAt` сделано **опциональным** (`DateTime?`) для обратной совместимости
- ✅ Существующие сессии без `expiresAt` будут работать корректно
- ✅ При первом доступе к старой сессии автоматически устанавливается `expiresAt`

### 3. **Автоматическая миграция данных**
- ✅ Метод `decryptSessionData` автоматически определяет формат данных
- ✅ Если обнаружен старый формат, данные мигрируются в новый формат
- ✅ Миграция сохраняется в БД асинхронно, не блокируя основной поток

## 🔄 Процесс миграции:

### Этап 1: Определение формата
```typescript
const hasOldFormat = session.cookiesEncrypted || session.localStorageEncrypted;
const hasNewFormat = session.sessionData && session.sessionData.trim() !== '';
```

### Этап 2: Чтение данных
- **Старый формат**: Используется `decrypt()` из `@/lib/encryption` (AES-256-CBC)
- **Новый формат**: Используется `decrypt()` из `UnifiedWBSessionManager` (AES-256-GCM)

### Этап 3: Конвертация
- Старые данные извлекаются и преобразуются в структуру `UnifiedSessionData`
- Создается отпечаток целостности (fingerprint)
- Устанавливается версия формата (`3.0-unified`)

### Этап 4: Сохранение (в фоне)
- Данные шифруются новым алгоритмом (AES-256-GCM)
- Сохраняются в поле `sessionData`
- Устанавливается `expiresAt` если его не было

## 📋 План миграции Prisma:

### Шаг 1: Создать миграцию (БЕЗОПАСНО)
```bash
npx prisma migrate dev --name add_expires_at_optional --create-only
```

### Шаг 2: Проверить сгенерированную миграцию
Убедитесь, что миграция:
- ✅ Добавляет поле `expires_at` как **nullable** (не обязательное)
- ✅ **НЕ** удаляет существующие данные
- ✅ **НЕ** изменяет существующие поля `cookies_encrypted`, `local_storage_encrypted`, `session_storage_encrypted`

### Шаг 3: Применить миграцию
```bash
npx prisma migrate deploy
```

### Шаг 4: (Опционально) Миграция данных
Если хотите мигрировать все данные сразу:
```bash
node migrate-sessions.js
```

## 🚨 Важные предупреждения:

1. **НЕ удаляйте старые поля** `cookiesEncrypted`, `localStorageEncrypted`, `sessionStorageEncrypted` сразу
2. **Сначала убедитесь**, что все сессии успешно мигрированы
3. **Резервная копия БД** должна быть создана перед миграцией

## 🔍 Проверка миграции:

После применения миграции проверьте:

1. **Старые сессии читаются корректно:**
   ```sql
   SELECT id, user_id, cookies_encrypted, session_data 
   FROM wb_sessions 
   WHERE cookies_encrypted IS NOT NULL;
   ```

2. **Новые сессии создаются в новом формате:**
   ```sql
   SELECT id, user_id, session_data, expires_at 
   FROM wb_sessions 
   WHERE session_data IS NOT NULL;
   ```

3. **Автоматическая миграция работает:**
   - Проверьте логи на наличие сообщений `"Detected old session format, migrating to new format"`
   - После первого чтения старые сессии должны иметь заполненное поле `session_data`

## ✅ Гарантии безопасности:

- ✅ **Существующие данные не удаляются**
- ✅ **Старые форматы поддерживаются автоматически**
- ✅ **Миграция происходит "на лету" при первом доступе**
- ✅ **Ошибки миграции не блокируют работу системы**
- ✅ **Двойная защита**: если новый формат не читается, пытаемся прочитать старый

## 📝 Что происходит при чтении старой сессии:

1. Код определяет, что `sessionData` пусто, но есть `cookiesEncrypted`
2. Автоматически вызывается `migrateOldFormatToNew()`
3. Старые данные расшифровываются через старый алгоритм
4. Данные преобразуются в новый формат
5. В фоне сохраняются в новый формат (не блокируя текущую операцию)
6. Возвращаются данные пользователю

**Результат**: Пользователь получает свои данные, система автоматически мигрирует их в фоне! 🎉
