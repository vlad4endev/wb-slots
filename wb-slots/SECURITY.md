## Сообщение об уязвимости

Мы серьезно относимся к безопасности WB Slots. Если вы обнаружили уязвимость безопасности, пожалуйста, сообщите об этом как можно скорее.

### Как сообщить

**Пожалуйста, НЕ сообщайте об уязвимостях безопасности через публичные GitHub issues.**

Вместо этого отправьте отчет по одному из следующих каналов:

- 📧 **Email**: security@wb-slots.com
- 🔒 **PGP**: [Ключ безопасности](https://wb-slots.com/security.asc)
- 💬 **Telegram**: [@wb_slots_security](https://t.me/wb_slots_security)

### Что включить в отчет

Пожалуйста, включите следующую информацию в ваш отчет:

- Описание уязвимости
- Шаги для воспроизведения
- Потенциальное воздействие
- Предлагаемые исправления (если есть)
- Ваша контактная информация

### Что ожидать

- **Подтверждение получения** в течение 24 часов
- **Первоначальная оценка** в течение 72 часов
- **Обновления** каждые 7 дней до разрешения
- **Публичное раскрытие** после исправления (если применимо)

## Безопасность в коде

### Шифрование

- **Токены WB API** шифруются с использованием AES-GCM
- **Пароли** хешируются с помощью bcryptjs
- **JWT токены** подписываются с использованием HMAC-SHA256

### Аутентификация

- JWT токены имеют ограниченный срок жизни (7 дней)
- Реализована система ролей (USER, ADMIN, DEVELOPER)
- Row Level Security (RLS) для изоляции данных пользователей

### API безопасность

- Rate limiting для предотвращения злоупотреблений
- Валидация всех входящих данных
- CORS настройки для ограничения доступа
- Маскирование чувствительных данных в логах

### База данных

- Подключения к БД через SSL
- RLS политики для мультитенантности
- Регулярные резервные копии
- Мониторинг подозрительной активности

## Рекомендации по безопасности

### Для пользователей

1. **Используйте сильные пароли** (минимум 12 символов)
2. **Регулярно обновляйте** токены WB API
3. **Не делитесь** учетными данными
4. **Включайте 2FA** где это возможно
5. **Мониторьте** активность в аккаунте

### Для разработчиков

1. **Следуйте** принципам безопасного кодирования
2. **Используйте** последние версии зависимостей
3. **Проводите** регулярные аудиты безопасности
4. **Тестируйте** на уязвимости
5. **Документируйте** изменения безопасности

1. **Обнаружение** уязвимости
