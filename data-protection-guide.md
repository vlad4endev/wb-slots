# 🛡️ Руководство по защите пользовательских данных

## 🎯 Проблема

При обновлениях проекта часто происходит потеря пользовательских данных из-за:
- Выполнения `docker-compose down -v` (удаляет все volumes)
- Пересоздания контейнеров без сохранения данных
- Неправильного применения миграций базы данных

## 📊 Анализ мест хранения данных

### 1. База данных PostgreSQL
**Местоположение:** Docker volume `wb-slots_postgres_data`
**Содержит:**
- Пользователи и их профили (`users`)
- Токены WB API (`user_tokens`) - **КРИТИЧНО**
- Настройки пользователей (`user_settings`)
- Сессии WB (`wb_sessions`) - **КРИТИЧНО**
- Задачи и результаты поиска (`tasks`, `runs`, `found_slots`)
- Настройки складов (`warehouse_prefs`)
- История аудита (`audit_logs`)

### 2. Redis
**Местоположение:** Docker volume `wb-slots_redis_data`
**Содержит:**
- Сессии приложения
- Очереди задач
- Кэш данных

### 3. Конфигурационные файлы
**Местоположение:** Файловая система
**Содержит:**
- `.env` файлы с настройками
- `docker-compose.yml` конфигурации
- Настройки Telegram бота

## 🛠️ Решение - Система защиты данных

### Автоматические скрипты

#### 1. `backup-user-data.bat` - Резервное копирование
```bash
# Создает полную резервную копию:
- База данных PostgreSQL (SQL дамп)
- Данные Redis (RDB файл)
- Docker volumes (архивы)
- Конфигурационные файлы
- Сжатый архив с временной меткой
```

#### 2. `restore-user-data.bat` - Восстановление
```bash
# Восстанавливает данные из резервной копии:
- Выбор из доступных резервных копий
- Безопасное восстановление БД
- Восстановление volumes
- Восстановление конфигураций
```

#### 3. `safe-update.bat` - Безопасное обновление
```bash
# Обновляет проект с сохранением данных:
- Автоматическое создание резервной копии
- Обновление кода из Git
- Обновление зависимостей
- Применение миграций БД
- Запуск с сохранением данных
```

## 📋 Пошаговые инструкции

### 🔄 Обычное обновление (БЕЗОПАСНО)

```bash
# Используйте безопасное обновление
safe-update.bat
```

**Что происходит:**
1. ✅ Автоматическое создание резервной копии
2. ✅ Остановка сервисов
3. ✅ Обновление кода из Git
4. ✅ Обновление зависимостей
5. ✅ Применение миграций БД
6. ✅ Запуск с сохранением данных

### 💾 Ручное резервное копирование

```bash
# Создание резервной копии
backup-user-data.bat
```

**Результат:** Файл `backups/wb-user-data-backup-YYYY-MM-DD-HH-MM-SS.zip`

### 🔄 Восстановление данных

```bash
# Восстановление из резервной копии
restore-user-data.bat
```

**Процесс:**
1. Выбор резервной копии из списка
2. Подтверждение операции
3. Восстановление всех данных
4. Запуск сервисов

## ⚠️ Критические моменты

### ❌ НЕ ДЕЛАЙТЕ ЭТО:

```bash
# НИКОГДА не используйте эти команды при обновлении:
docker-compose down -v          # Удаляет все данные!
docker system prune -a          # Удаляет все образы и volumes!
docker volume prune             # Удаляет все volumes!
```

### ✅ ПРАВИЛЬНЫЕ команды:

```bash
# Остановка без удаления данных
docker-compose down

# Очистка только неиспользуемых образов (БЕЗ volumes)
docker image prune

# Безопасное обновление
safe-update.bat
```

## 🔧 Дополнительные меры защиты

### 1. Регулярные резервные копии

Создайте задачу в планировщике Windows для автоматического резервного копирования:

```batch
# Ежедневно в 2:00 ночи
schtasks /create /tn "WB-Slots-Backup" /tr "C:\path\to\backup-user-data.bat" /sc daily /st 02:00
```

### 2. Мониторинг состояния данных

```bash
# Проверка состояния volumes
docker volume ls

# Проверка размера данных
docker system df

# Проверка состояния БД
docker exec wb-slots-postgres psql -U postgres -c "\dt"
```

### 3. Тестирование восстановления

Регулярно тестируйте процесс восстановления:

```bash
# 1. Создайте тестовую резервную копию
backup-user-data.bat

# 2. Остановите сервисы
docker-compose down

# 3. Восстановите данные
restore-user-data.bat

# 4. Проверьте работоспособность
```

## 🚨 Экстренное восстановление

### Если данные потеряны:

1. **Остановите все сервисы:**
   ```bash
   docker-compose down
   ```

2. **Найдите последнюю резервную копию:**
   ```bash
   dir backups\wb-user-data-backup-*.zip /od
   ```

3. **Восстановите данные:**
   ```bash
   restore-user-data.bat
   ```

4. **Проверьте работоспособность:**
   - Откройте http://localhost:3000
   - Проверьте авторизацию
   - Проверьте настройки пользователей

## 🔐 Безопасность резервных копий

### Рекомендации:
1. **Шифрование:** Храните резервные копии в зашифрованном виде
2. **Внешнее хранение:** Копируйте резервные копии на внешние носители
3. **Контроль доступа:** Ограничьте доступ к папке `backups`
4. **Ротация:** Удаляйте старые резервные копии (старше 30 дней)

### Пример скрипта очистки старых копий:

```batch
@echo off
echo Удаление резервных копий старше 30 дней...
forfiles /p backups /m wb-user-data-backup-*.zip /d -30 /c "cmd /c del @path"
echo Очистка завершена
```
